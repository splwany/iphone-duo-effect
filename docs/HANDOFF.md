# 项目交接说明

## 交接目标与状态

基线版本：全参数精调 23。用户已认可前一版本的磨砂视觉，并要求将可调效果全部开放为以当前默认为 50% 的滑块。11 项参数已实现，桌面浏览器已验证展开、持久化、重置与渲染；新增所有参数组合未完成 iPhone 真机穷举。

目标设备曾为 iPhone 14 Pro；用户报告 iOS 26.6.2，此版本信息来自用户，未独立核实。模拟的是“截图像停留在底页，手机像磨砂封皮掀开”的视觉错觉。不是折叠手机硬件模型，不控制系统桌面，不跟踪实际观看者或摄像机位置。

## 文件职责与数据流

- `web/index.html`：全部控件、帮助、诊断、PWA metadata。
- `web/style.css`：响应式预览与沉浸布局；有多轮追加覆盖，勿只读最前面的规则。
- `web/app.js`：本地导图、参数存储、体感权限、动画平滑、沉浸进出与布局诊断。
- `web/motion.js`：可单测的 TiltTracker 校准与重力方向估计。
- `web/render.js`：DepthRenderer，WebGL 2 顶点/片元程序、纹理上传与绘制。
- `web/sample.svg`、`icon.svg`：随包示例与图标；无用户截图。
- `web/manifest.webmanifest`：standalone 模式配置，无 service worker。
- `scripts/serve.py`：新整理的通用开发服务器，与原来绑定特定 IP 的私人脚本不同。

DeviceMotion → 扣除可用线性加速度 → 旋转屏幕坐标 → TiltTracker → target ∈ [-1,1] → 指数时间平滑 current → WebGL uniforms → 渲染。

文件选择 → ≤35 MB 检查 → 图片解码 → 长边最多 2600 px canvas → GPU 纹理。另生成 JPEG .94 供 CSS 回退使用，GPU 接收的是 canvas；不要误以为 GPU 使用了该 JPEG。截图只活在当前页面，设置存在 localStorage。

## 参数表

令 p 为滑块百分比 / 100。除模糊强度外均为 min+(max-min)*p。

| 控件 | 内部字段 | 范围 | 50% 内部值 |
|---|---|---|---|
| 模糊强度 | blurStrength | 0–0.2 | 0.1 |
| 横向拉伸 | horizontalStretch | 0.8–1 | 0.9 |
| 远端内缩 | farShrink | 0–0.26 | 0.13 |
| 模糊加速 | blurCurve | 1–3 | 2 |
| 散射集中度 | scatterFocus | 0–4 | 2 |
| 横向散射 | scatterX | 0–4 | 2 |
| 纵向散射 | scatterY | 0–2 | 1 |
| 大角度扩散 | grazingRange | 0.25–0.75 | 0.5 |
| 边缘柔化 | edgeSoftness | 0.5–1.5 | 1 |
| 细节融合 | blurBlend | 0.4–1 | 0.7 |
| 跟手平滑 | followSmooth | 10–60 ms | 35 ms |

所有默认均为 50%，但已保存的非默认值继续保留。按钮“所有效果恢复 50%”重置效果参数，不重置校准、图像或手动角度。

存储：模糊 `fold-blur-strength-v2`，横向拉伸 `fold-horizontal-stretch-v2`，远端内缩 `fold-far-shrink-v2`；其他 `fold-控件ID-v1`，具体以 app.js 绑定为准。模糊旧 10% → 新 50%；旧拉伸 90% → 新 50%；旧内缩 13% → 新 50%。旧值超出新范围会钳制，不能声称所有旧设置完全等效。

## 当前渲染公式

令 θ=abs(current)·π/2，u 为距当前近端的归一化横坐标（左右倾斜时翻转），W/H 为 CSS 尺寸。

```text
depth = u·sin(θ)
几何垂距 d = W·depth
散射角 α = blurStrength·π/6
基础模糊半径 R = W·tan(α)·depth^blurCurve
```

当前默认 blurCurve=2，因此前期/近端慢、后期/远端快。这是艺术化距离响应，不是实测材料定律。旧线性距离版本与现在不同。

```text
横向采样位置 = u·[(1-horizontalStretch)+horizontalStretch·cos(θ)]
纵向比例 = 1-0.65·farShrink·depth
采样 y = 0.5+(uv.y-0.5)/纵向比例
c = sqrt(cos²(θ)+(1-grazingRange)²·sin²(θ))
Rx = R·c^(-scatterX)
Ry = R·c^(-scatterY)
```

这个椭圆模型是小角度光线交平面的视觉近似，并把观看倾角视为翻开角。没有真实折射率、厚度、双面折射或实测 BTDF。默认 θ=90° 时扩展轴倍率为 4 和 2；高级滑块极端组合横轴倍率可到 256，仍有限但会严重失去细节，未来应考虑收窄范围或软上限。

12 对对称采样，共 24 次；半径 r=sqrt((i+0.5)/12)，方位角=(i+0.5)·2.39996323，权重 exp(-scatterFocus·r²)，最终除以权重和。纹理用 SRGB8_ALPHA8，颜色在线性空间采样混合，输出做分段 sRGB 编码。mipmap + 截断高斯近似不等于严格高斯卷积。

LOD 取基础缩小等级与由 min(Rx,Ry)·图像高/H·blurBlend 推导等级的较大者。边缘 coverage 使用与 LOD 对应的 smoothstep 宽度乘 edgeSoftness，每次采样都携带覆盖率；最终不再锐利裁切。图片外颜色以边缘延拓，覆盖率向外渐消失到黑底。因此移除“变暗”不代表边界不会与黑底融合。

额外整体变暗与 90° 强制全黑已按用户要求移除，不要擅自恢复。

## 体感约束

TiltTracker 过滤重力幅度 6–14；稳定校准需至少 800 ms / 12 个样本，方向波动阈值 2.5°。基准过于侧立会拒绝校准。传感器平滑常数 45 ms，显示跟手平滑默认 35 ms，这两层不同。没有陀螺仪积分或自动回中，避免持续漂移；极端姿势、移动加速度和重力方向退化仍会影响估计。前后倾斜不作为单独的交互控制，不保证任意三维旋转都完全解耦。

## 最容易回归的全屏问题

历史症状：截图顶部偏移、两侧黑边、底部大黑边。主屏幕曾读到 screen 393×852，但 innerHeight/visualViewport 只有 793（差 59）。用户确认修复有效后一直保留该方案。

关键组合：viewport-fit=cover；black-translucent 状态栏；standalone 沉浸时根元素不固定定位；stage 移出 app 放到 body，用正常文档中的 absolute 定位；由 screen 比例推导全屏高度。退出时用 placeholder 恢复 DOM 与滚动位置。不要为了底部黑边再次直接把根改成 fixed，或反复叠加安全区 padding。

图片按比例 contain，非屏幕比例图片可能合理留黑边；Safari 普通页面和主屏幕模式必须分开测。截图自带时间/电池会与系统状态栏叠加，这不是模糊故障。主屏幕 metadata 变更可能需要重新添加图标，普通代码更新不应要求反复安装。

## 已知限制与下一步

- 没有构建工具、模块拆分或统一参数 schema；字段目前分散在 HTML、绑定、uniform 默认和文档。建议先提取配置表并写中点等价测试。
- style.css 有历史覆盖；重构前保存真机基线。
- 无 WebGL2 时只有静态 CSS 回退，没有同等动画或明确能力提示。
- 连续 requestAnimationFrame，静止时仍绘制；可后续增加 dirty rendering、后台节流与性能档位。
- 最大 DPR=1.5，最多 2600 px 图像；低端设备仍需实测。
- 无离线支持、图像持久化、配置导入导出、自启守护。不要误称已实现。
- 安全连接错误文案仍提到局域网 8443，部署公网站点时应泛化。
- 原 work/check-motion.cjs 是过期测试，未复制；本包新增 motion 测试只覆盖实际当前 Tracker，不代表覆盖 UI/WebGL。
- 当前仍可能发生极端参数下采样纹理、边缘延拓色带、真实光学不一致；用具体截图和角度逐项比较。

## 回归清单

1. 桌面手动 0、±15、±45、±90°：不报错，左右镜像，0°清晰。
2. 同一截图测试模糊 0/50/100；零模糊时不应凭空增加散射。
3. 所有 50% 与本次基线一致；逐项改变、刷新保留、恢复 50%。
4. iPhone HTTPS 权限允许/拒绝；校准、静止保持、暂停体感、手动切换。
5. 主屏幕沉浸进出、旋转、后台返回；顶部底部与两侧，退出后的滚动位置。
6. 屏幕比例截图与其他比例图片，大小边界/损坏文件；GPU context 丢失时的回退。
7. 真机连续使用关注帧率、发热；浏览器检查不能替代这些结论。
